> - `expression`: `expr`/`expression` required, ≤`MAX_EXPR_LEN` (200) chars, blocklist substrings (`;`, `&amp;&amp;`, `||`, `` ` ``, `$(`, `system`, `call `, `fork`, `exec`) case-insensitive.

> ## `Evidence` (tracecli_debugger/evidence.py)
> ```python
> @dataclass
> class Evidence:
>     event: str
>     raw: str
>     data: Dict[str, Any] = field(default_factory=dict)
> 
>     def to_dict(self) -&gt; Dict[str, Any]:
>         out = {"event": self.event}
>         out.update(self.data)
>         out["raw"] = self.raw
>         return out
> ```
> So the JSON shape of every evidence event is `{"event": &lt;str&gt;, ...data fields..., "raw": &lt;str&gt;}`. Event names produced by `DebuggerSession` (see below): `session_started`, `breakpoint_set`, `breakpoint_event`, `command_result`, `signal`, `process_exit`, `stack_frame`, `variable`, `register`, `frame_selected`, `invalid_action`, `debugger_error`, `timeout`.

> ## `DebuggerSession` (tracecli_debugger/session.py)
> ```python
> class DebuggerSession:
>     def __init__(self, executable: str, gdb_path: str = "gdb", timeout: float = 10.0)
>     def launch(self) -&gt; List[Dict[str, Any]]
>     def close(self) -&gt; None
>     def execute(self, action_dict: Dict[str, Any]) -&gt; List[Dict[str, Any]]
>     def execute_many(self, actions: List[Dict[str, Any]]) -&gt; List[Dict[str, Any]]
> ```
> - Constructor immediately constructs a `GDBAdapter(executable, gdb_path=gdb_path, timeout=timeout)`, which raises `GDBNotFoundError` if `gdb` isn't on `PATH`, or `FileNotFoundError` if the executable doesn't exist — **both are raised synchronously from `DebuggerSession.__init__`**, not deferred to `launch()`.
> - `execute()` auto-launches if `launch()` wasn't called explicitly (`session.py:65-72`), catches `GDBTimeoutError`/`GDBNotFoundError`/`GDBStartupError` internally and turns them into `Evidence` dicts (`timeout` / `debugger_error` events) rather than propagating exceptions — so **`execute`/`execute_many` never raise** for those cases; invalid actions similarly produce `invalid_action` evidence rather than raising.
> - `execute_many(actions: List[Dict]) -&gt; List[Dict]` just concatenates `execute()` results in order (`session.py:81-86`) — this is the natural entry point for Part 4 to hand a `PlanResult.actions` list straight through.
> - This is a pure Python API — there is no `__main__.py` for the package itself, but there IS a dedicated subprocess/stdio entrypoint in `protocol.py` (see below).

> ## Transport / invocation from Rust side
> There is **no existing Rust→Python glue at all**. Confirmed by `grep -rn "python\|pyo3\|Command::new" src/` — the only `Command::new` calls are for the target executable (`execution.rs:74`) and compiler/`file`/`nm` detection (`build_context.rs`), none reference Python.
> 
> However, Part 2 ships an **established transport** ready for Part 4 to use: `tracecli_debugger/protocol.py` (`protocol.py:1-71`):
> ```
> python -m tracecli_debugger.protocol /path/to/executable
> ```
> Protocol: newline-delimited JSON over stdio.
> - On startup, `DebuggerSession(executable)` is built and `.launch()` is called; each resulting evidence dict is printed as one JSON line to stdout (flushed).
> - Then the process reads stdin line-by-line: each line must be a JSON `DebugAction`-shaped dict; `session.execute(action)` is called and every evidence dict is printed as one line to stdout, flushed immediately.
> - Sending the literal line `__close__` (or closing stdin) causes `session.close()` and a clean exit (0).
> - On stdin JSON decode error, emits `{"event": "invalid_action", "error": "invalid JSON: ...", "raw": line}`.
> - On session construction failure, emits `{"event": "debugger_error", "message": str(e)}` and `sys.exit(1)`.
> 
> This is exactly the shape Part 4 (Rust) would use via `std::process::Command::new("python3").args(["-m", "tracecli_debugger.protocol", executable])` with piped stdin/stdout — confirmed working end-to-end by `tests/test_debugger.py::test_21_protocol_ipc` (`test_debugger.py:321-371`), which is the closest thing to a reference implementation of the IPC pattern Part 4 should follow.
> 
> Alternative for Part 4: since `tracecli_llm` (Part 3) is explicitly designed to be driven as an importable Python library (`build_engines()`, `planner.plan()`, `debugger_session.execute_many()`), an all-Python orchestrator module could import both `tracecli_debugger` and `tracecli_llm` directly in-process rather than going through the stdio protocol — the HANDOFF.md's "Next 3 things" note explicitly assumes this in-process style (`DebuggerSession.execute_many()` called directly, not via `protocol.py`). Both transports exist and are valid; Part 4 needs to pick one.

> ## Exception hierarchy (tracecli_llm/errors.py)
> ```python
> class LLMEngineError(Exception): ...
> class ProviderError(LLMEngineError): ...
> class AuthenticationError(ProviderError): ...     # never retried; e.g. missing/invalid API key
> class RateLimitError(ProviderError): ...          # HTTP 429; retried w/ backoff
> class ProviderTimeoutError(ProviderError): ...    # request timeout; retried
> class NetworkError(ProviderError): ...            # DNS/connection reset; retried
> class ProviderResponseError(ProviderError): ...   # 5xx / unexpected status / empty response; retried
> class OutputValidationError(LLMEngineError):
>     def __init__(self, message: str, *, raw_output: str = ""): ...
>     # .raw_output carries the offending model text
> ```
> `AuthenticationError` is also raised directly by `LLMConfig.api_key()` (config.py:68-81) when the configured env var is unset/empty, and by `GeminiProvider.__init__` if `api_key` is falsy. `OutputValidationError` is raised by `validate_planner_output`/`validate_diagnosis_output` in schemas.py, and re-raised by `DebugPlanner.plan`/`DiagnosisEngine.diagnose` after exhausting one corrective retry.
